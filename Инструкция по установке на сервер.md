# Установка и обновление Gently Connect

Это руководство для проекта `Dating-Landing-Builder` и VPS с Ubuntu 22.04/24.04. Сайт статический: после сборки Nginx раздаёт HTML, CSS и JavaScript. База данных и отдельный API-сервер не нужны. Node.js и pnpm используются на VPS только для сборки.

## 1. Перед покупкой домена и VPS

Для Индии и возможной смены страны подойдёт международная зона `.com`. Рабочее название бренда — **Gently Connect**, а `gentlyconnect.com` — только кандидат: перед оплатой проверьте у регистратора доступность домена, цену продления и возможные конфликты с чужими брендами. Покупка домена не включает VPS или веб-хостинг.

Для этого руководства нужен VPS с Ubuntu 22.04/24.04, публичным IPv4-адресом и доступом по SSH. При заказе сохраните IP-адрес сервера и данные для SSH. Подключайтесь обычным пользователем с правом `sudo`, а не под `root`.

## 2. Заполните данные сайта перед публикацией

Откройте `artifacts/dating-landing/src/config.ts` и проверьте поля:

- `PARTNER_URL` — точная HTTPS-ссылка из партнёрской сети со всеми нужными параметрами.
- `SITE_OPERATOR_NAME` — настоящее имя владельца сайта или его компании. `Gently Connect` — бренд, а не юридическое лицо.
- `HOSTING_PROVIDER` — фактический хостинг и проверенные сведения о технических журналах.
- `PRIVACY_CONTACT_EMAIL` уже заполнен; убедитесь, что этот адрес можно публиковать.

Пока `PARTNER_URL` пустой или не начинается с `https://`, кнопка партнёра остаётся выключенной. Сначала третье нажатие показывает результат, затем отдельная кнопка партнёра открывает заданную ссылку в новой вкладке после подтверждения возраста 18+.

Репозиторий проекта публичный, а ссылка встраивается в клиентский JavaScript сайта. Посетитель сможет её увидеть. Не помещайте туда пароль, API-ключ или иной секрет; добавляйте только партнёрскую ссылку, которую разрешено показывать публично. Не публикуйте сайт, пока имя владельца или хостинг в политике остаются в квадратных скобках. Перед запуском проверьте правила оффера и рекламного источника.

## 3. После покупки домена настройте DNS в REG.RU

Сначала узнайте у VPS-провайдера IPv4-адрес сервера. Если провайдер выдал свои DNS-серверы, следуйте его инструкции и редактируйте записи именно в панели, которая обслуживает DNS-зону. При смене NS записи в старой панели REG.RU перестанут действовать.

Если VPS внешний, а DNS-зоной хотите управлять в REG.RU:

1. Войдите в личный кабинет REG.RU и откройте **Домены**.
2. Выберите свой домен, откройте управление и блок **DNS-серверы и управление зоной**.
3. Укажите DNS-серверы REG.RU `ns1.reg.ru` и `ns2.reg.ru`, подтвердите изменение.
4. После этого в блоке управления зоной добавьте две записи типа **A**:

   | Поддомен | Тип | Значение |
   | --- | --- | --- |
   | `@` | A | IPv4-адрес VPS |
   | `www` | A | тот же IPv4-адрес VPS |

5. Удалите только конфликтующие записи для `@` или `www`, если они направляют сайт на другой сервер. Не удаляйте почтовые `MX`/`TXT` записи, если пользуетесь почтой на домене.

Не добавляйте `AAAA`, если провайдер не выдал и не настроил IPv6. Для `www` используйте либо запись `A`, либо `CNAME` на основной домен — не создавайте оба типа для одного имени.

Если вы заказали VPS у REG.RU, не копируйте NS-пару для обычного DNS автоматически: для некоторых VPS используются `ns5.hosting.reg.ru` и `ns6.hosting.reg.ru`, а зона управляется в DNSAdmin или панели сервера. Для хостинга сайтов REG.RU используются другие NS. Выберите вариант, который REG.RU показывает для именно вашей услуги, и создавайте записи в соответствующей панели.

Обновление DNS может занять до 24 часов. Проверить A-записи можно так:

```sh
dig +short A example.com @1.1.1.1
dig +short A www.example.com @1.1.1.1
```

Замените `example.com` на свой домен. В обоих ответах должен появиться IPv4-адрес VPS.

Официальные инструкции REG.RU: [привязка домена к VPS](https://help.reg.ru/support/klassicheskie-vps/osnovi-raboty-s-vps/kak-privyazat-domen-k-vps), [изменение DNS-серверов](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/kak-propisat-dns-dlya-domena-v-lichnom-kabinete-reg-ru), [добавление DNS-записей в личном кабинете](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-v-lichnom-kabinete).

## 4. Получите исходники из GitHub

Исходники находятся в публичном репозитории [arteksrab-cmyk/dating_site](https://github.com/arteksrab-cmyk/dating_site). Для `git clone` публичного репозитория не нужен пароль или GitHub-токен:

```sh
git clone https://github.com/arteksrab-cmyk/dating_site.git
cd dating_site
```

Рекомендуемый порядок изменений: отредактируйте `artifacts/dating-landing/src/config.ts` на своём компьютере или через редактор GitHub, сохраните коммит в репозитории, а на сервере выполните `git pull --ff-only`. Не редактируйте рабочую копию только на VPS: такие изменения не попадут в GitHub и могут конфликтовать при следующем обновлении.

Если редактируете на компьютере через Git:

```sh
git add artifacts/dating-landing/src/config.ts
git commit -m "Configure site settings"
git push
```

## 5. Подготовьте VPS и установите Node.js

Подключитесь к серверу по SSH с компьютера:

```sh
ssh USER@SERVER_IP
```

Замените `USER` и `SERVER_IP` на данные своего VPS. Установите инструменты:

```sh
sudo apt update
sudo apt install -y git curl ca-certificates nginx certbot python3-certbot-nginx rsync dnsutils
```

Для сборки нужны Node.js 24 и pnpm 10. Если они уже установлены, пропустите установку и проверьте версии командами `node --version` и `pnpm --version`. Иначе в обычной SSH-сессии Bash установите Node.js через nvm:

```sh
curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.bashrc
nvm install 24
nvm use 24
npm install --global pnpm@10
node --version
pnpm --version
```

Затем клонируйте репозиторий на сервер, если ещё не сделали это в шаге 4:

```sh
cd ~
git clone https://github.com/arteksrab-cmyk/dating_site.git
cd ~/dating_site
```

Если каталог `~/dating_site` уже есть, второй раз клонировать не нужно — перейдите в него командой `cd ~/dating_site`.

## 6. Соберите сайт и установите его в Nginx

В корне репозитория выполните:

```sh
pnpm install --frozen-lockfile
pnpm --filter @workspace/dating-landing run typecheck
PORT=3000 BASE_PATH=/ pnpm --filter @workspace/dating-landing run build
```

Готовые статические файлы появятся в `artifacts/dating-landing/dist/public/`. Создайте отдельную папку сайта:

```sh
sudo mkdir -p /var/www/gentlyconnect
sudo chown -R "$USER":www-data /var/www/gentlyconnect
```

Скопируйте сборку:

```sh
sudo rsync -a --delete artifacts/dating-landing/dist/public/ /var/www/gentlyconnect/
sudo chown -R www-data:www-data /var/www/gentlyconnect
```

`--delete` удаляет в целевой папке файлы, которых нет в новой сборке. Используйте эту команду только для выделенной папки этого сайта; перед первой заменой сохраните её содержимое, если там уже лежат нужные файлы.

## 7. Настройте Nginx

Создайте конфигурацию сайта:

```sh
sudo nano /etc/nginx/sites-available/gentlyconnect
```

Вставьте конфигурацию, заменив `example.com` и `www.example.com` на свой домен:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;

    root /var/www/gentlyconnect;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location ~* \.(css|js|svg|ico|png|jpg|jpeg|webp|woff2)$ {
        try_files $uri =404;
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

Сохраните файл, включите конфигурацию и проверьте её:

```sh
sudo ln -s /etc/nginx/sites-available/gentlyconnect /etc/nginx/sites-enabled/gentlyconnect
sudo nginx -t
sudo systemctl reload nginx
```

Если `ln` сообщает, что ссылка уже существует, не создавайте её повторно. Если `nginx -t` показывает ошибку, исправьте её и повторяйте проверку, пока она не пройдёт.

До HTTPS проверьте, что DNS уже указывает на VPS и сайт открывается по HTTP:

```sh
curl -I http://example.com
```

## 8. Включите HTTPS

Когда домен открывается по HTTP, получите сертификат:

```sh
sudo certbot --nginx -d example.com -d www.example.com
sudo certbot renew --dry-run
```

Следуйте подсказкам Certbot и включите перенаправление с HTTP на HTTPS. Если используете UFW, заранее разрешите SSH и веб-трафик; если входящие подключения фильтруются панелью VPS, откройте порты 80 и 443 там. Не включайте файрвол, пока не разрешили SSH, иначе можно потерять доступ к серверу.

## 9. Обновляйте сайт после изменений в GitHub

Сначала сохраните изменения в публичном репозитории. Затем на VPS выполните:

```sh
cd ~/dating_site
git pull --ff-only
pnpm install --frozen-lockfile
pnpm --filter @workspace/dating-landing run typecheck
PORT=3000 BASE_PATH=/ pnpm --filter @workspace/dating-landing run build
sudo rsync -a --delete artifacts/dating-landing/dist/public/ /var/www/gentlyconnect/
sudo chown -R www-data:www-data /var/www/gentlyconnect
sudo nginx -t && sudo systemctl reload nginx
```

Если вы меняли зависимости, `pnpm install` применит обновлённый lock-файл. Если серверная папка отличается от GitHub, сначала сохраните нужные изменения и приведите её к версии репозитория; не используйте принудительный сброс Git, чтобы не потерять файлы.

## 10. Проверьте перед запуском трафика

- Основной домен и `www` открываются по HTTPS на компьютере и телефоне.
- После третьего вопроса появляется результат, а переход к партнёру идёт отдельной кнопкой.
- Подтверждение возраста 18+ обязательно; CTA ведёт на проверенный оффер.
- Политика, cookie-настройки и партнёрское раскрытие доступны внизу страницы.
- В политике заполнены реальное имя оператора, публичный контакт и сведения о хостинге; нет квадратных скобок или шаблонных значений.
- Партнёрская сеть и рекламный источник разрешают такой прелендинг и выбранный трафик.

Ответы на вопросы остаются в памяти открытой страницы и не отправляются сайту. Выбор cookie хранится в локальном браузере, чтобы запомнить решение. На странице не включены аналитические и рекламные трекеры. Хостинг всё равно может обрабатывать технические запросы и вести журналы, а сайт партнёра действует по собственной политике.
